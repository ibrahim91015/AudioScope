# AudioScope 0.5.2 — call-safe mic capture, carrier mixing and recent activity

Automatic app/VoIP calls and identified Wi-Fi telephony calls now request **VoIP playback + Communication mic**. Cellular calls request **uplink and downlink separately**. IWLAN voice registration identifies Wi-Fi telephony when Android exposes it; otherwise a silent/failed carrier pair adds the VoIP routes. If those routes actually become audible, their general mix becomes the default player instead of a silent carrier mix. OEM transport reporting and source availability still need phone acceptance.

**Communication mic uses the capture helper by default when connected.** It first tries non-private VOICE_COMMUNICATION. During a call, recovery can reopen a lost recorder or use helper MIC if the communication preset is reported silenced for 1.5 seconds or returns digital zeros for five seconds. This follows CallVault's call-safe near-party approach without repeatedly switching with UI focus. Detailed Sources shows the actual device, preset, backend, silencing and recovery explanation; these fields are also saved in the manifest. A quiet call can trigger the zero-buffer fallback. Disable recovery in Advanced settings for strict preset experiments. Without a connected helper, Android can still silence local capture beside a call app.

**Previews while recording** in Advanced settings offers three modes: pause with per-source resume (default), always pause, or continue non-conflicting previews. Every source has a Start monitoring control when its preview is paused/off. Recording sources reuse their own waveform; conflicting physical inputs and duplicate helper pipes stay blocked. Startup reserves the recording source and closes conflicting previews before capture. Manual preview handoff is serialized so it cannot close a newly opened preview. Hiding a source also clears its preview ownership.

**Carrier mix** is a separate mono file containing available uplink/downlink tracks only. Strong normalization balances gated per-track RMS toward −16 dBFS, permits up to about 30 dB boost and soft-limits peaks. Quiet noise can become louder. Originals remain unchanged in the full-screen view. Carrier both is moved to Hidden sources; unmodified defaults now show Communication mic in its place. Custom visibility/order is otherwise retained.

**Auto recommendations** retain any source with measured activity above the silence threshold within the last five seconds. Advanced settings changes that window and the minimum move interval (default four seconds). Promotion settles for 0.7 seconds, moves existing cards with a short animation and never writes the saved layout. Visible sources stay in their existing group; hidden sources do not jump into the visible group. After fifteen quiet seconds, or when recommendations are disabled, the saved order returns.

**12-hour AM/PM clocks** are the default. Appearance → Use 24-hour time applies at display time to older and new recordings, metadata, alerts and app logs, and to new export names. Elapsed durations and internal identifiers retain their own formats. Each full-screen recording ends with all persisted session metadata, nested/unknown fields, track health/routes, call details, bookmarks, export information and a session file inventory. Metadata values are selectable.

Clean signed/debug/test builds, 38 unit tests, seven emulator cases and rendered review are recorded in [validation](VALIDATION.md). The owned-helper test verifies actual communication PCM frame continuity after Home and actual-input metadata, without a real VoIP call. Real Samsung/CMF concurrent-call behavior, Wi-Fi transport classification and carrier audibility remain device checks.

Finish recording before updating. **Reconnect the helper after installation: this release uses bridge API 4.** Existing helper API 3 is rejected and must be restarted. The signing certificate is unchanged.

These explain the ordinary-app policy limits and the upstream helper MIC design; they do not establish every OEM's outcome.
